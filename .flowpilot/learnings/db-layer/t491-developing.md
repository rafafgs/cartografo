### t491 (developing, unverified)

- AT8 could not use `SELECT count(*) FROM runner`: scripts/check-single-writer.mjs forbids every SQLite driver (better-sqlite3, node:sqlite, ...) to any file outside packages/core/src/db, test files included, so importing one from packages/runner fails `npm run lint`. The proof is an existence oracle instead — `POST /v1/runners/:id/probes` answers 404 unknown_runner before it ever looks at the body, so it tells 'this id has a row' from 'it does not' for retired rows the listing hides. AT8 asserts the stable id has a row and that none of the three child pids' host+pid ids ever got one.
- The migration count is pinned in THREE places, not the two the previous ticket recorded: packages/core/test/migrate.test.ts (`applied.length`), packages/core/test/startup.test.ts (`readiness.migrationsApplied`) and now migrate.test.ts's own AT7 (`count(*) FROM schema_migrations`).
- `rtrim(rtrim(id, '0123456789'), '-')` groups the legacy ids by host, and a new-style id whose eight hex characters happen to be all decimal digits (~2.3% of hosts) would fall into the same group. Harmless today — such a row is the newest and therefore the survivor — but it is a real edge if this migration is ever re-run against a mixed table.
