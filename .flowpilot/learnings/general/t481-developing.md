### t481 (developing, unverified)

- `form label[for]` in style.css renders every labelled control's name at .8rem/var(--soft). An option's label IS the answer, not the label of one, so `.question-field .option` has to put it back to body size and var(--ink); without that override the whole radio list reads at the support grade.
- Deviation from the Code Changes table, deliberate: ONE `ANSWER_DOCUMENT_SCRIPT` shared by both pages rather than a per-page copy each. The hidden carrier marks itself `data-document`, so the field name — the only thing that differed between the two pages — is no longer in the script at all, and duplicating ~30 lines of hand-written JS would have doubled the risk for nothing.
- `accessibleNameOf` in questions-answer-field.test.ts asserts EXACTLY ONE naming label per control, so each option label both wraps its input and carries `for` (one label object, matched once). The hidden carrier is excluded from that sweep on purpose — a label pointing at an invisible field names nothing.
- A `recommended` value that is not among a field's own `options` is not dropped: it pre-fills the 'something else' box and ticks its control, which is the only honest place for it.
- The 'something else' radio/checkbox carries no `value`, so a scriptless plain POST would send `on` for it. Irrelevant today (only the assembled document is read) but a trap for anyone who later adds a no-script write path.
- The assembly script has no automated test: no browser here, and test/fake-dom.ts implements neither querySelector/querySelectorAll nor dataset (its own header says anything needing those is not testable there). Verified by hand-driving the script body against an object graph shaped like the emitted markup — choice -> string, multi -> array including the typed value, an untouched field contributes no key, a non-batched form is left alone.
- `cartografo up` ignores CARTOGRAFO_HOME and writes ./.cartografo inside whatever checkout it runs in (gitignored). Removed after the live check; ports 4527/4528 are free again and the three surviving `cartografo up` processes are other worktrees' (incl. pid 33944, the flowpilot test bench) and were not touched.
