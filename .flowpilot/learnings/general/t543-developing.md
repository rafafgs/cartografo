### t543 (developing, unverified)

- AT2 (kill-and-restart the control plane on a fixed port) had a real process leak on its first draft: the FIRST control-plane child had no `t.after` cleanup, only an explicit mid-test `.kill()` — so any assertion failure or timeout before that line left the process running with open stdio pipes, which is exactly what kept the whole `node --test` run from ever exiting during my red-check. Fixed by registering `t.after(() => first.kill())` immediately after spawning. Worth flagging for any future test that manages a child process outside the usual `cli-support.ts` helpers: register the cleanup before doing anything that can throw, never after.
- cli-support.ts's own `startControlPlane`/`runCli` couldn't serve two of this ticket's own needs (a backgrounded, still-readable CLI run for SIGINT/reconnect tests; a control plane pinned to a caller-chosen port+db across two process starts) — both were written as local helpers inside cli-watch.test.ts rather than added to cli-support.ts, since that file isn't in the ticket's declared shared-file surface and both needs are specific to this one file.
