### t675 (developing, unverified)

- `--deny-url '*'` is accepted by copilot 1.0.95 and denies NOTHING (shell curl and web_fetch both went through). The closed network is `--deny-tool url` (kind `url`, argument omitted = all URLs); a deny beats `--allow-all-tools`. `--allow-url` alone restricts nothing under `--allow-all-tools`, and the deny beats the allow, so a domain allowlist is not expressible and is refused. All of it is tool-level gating: a `python3` one-liner run by `shell` wrote outside the workspace under `--deny-tool write` and reached a loopback host under `--deny-tool url`.
- `copilot -p "-1 apples"` fails with `error: Invalid command format.`; `-p=-1 apples` delivers it intact. Skill instructions often start with `-` or `---`, so buildCommand emits `-p=<composed>` when the composition starts with a dash. FR2's literal `-p <text>` shape holds for every other input.
- `copilot --version` prints two lines (version, then an update hint); the probe keeps only the first. A fresh COPILOT_HOME already holds config.json ({firstLaunchAt}) with nobody logged in, and `login --help` names no credential file, so `authenticated` is env-only (COPILOT_GITHUB_TOKEN, GH_TOKEN, GITHUB_TOKEN).
- COPILOT_ALLOW_ALL is stripped from the engine environment whoever set it (exactly `true` also trusts the working directory and loads its hooks), and COPILOT_AUTO_UPDATE=false cannot be overridden by a node.
- Whole-workspace write emits NO path flag, but the CLI also allows the system temporary directory (`--disallow-temp-dir` exists and is deliberately not used, since builds write there). The confinement is to -C plus tmp, and only for the model's own file tools.
