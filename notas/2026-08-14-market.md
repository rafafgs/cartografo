# Mercado — existe isso hoje? (2026-08-14)

Varredura em 4 frentes (frameworks de orquestração, pesquisa produtizada,
onda 2026 de orquestradores de CLI, no-code + observabilidade), 37 projetos
únicos avaliados contra as 6 capacidades do README, e os 6 mais próximos
verificados adversarialmente contra docs/repos oficiais.

## Veredito

**O recorte combinado do cartografo não existe no mercado hoje.** Ninguém
entrega, como capacidade de runtime em produção, o par-núcleo síntese-de-grafo
+ evolução-entre-rodadas — muito menos casado com abstração de CLI, control
plane self-hosted, humano nas exceções e propostas gated. As peças existem
separadas, em famílias que não se falam.

## O que já virou commodity (não diferencia ninguém em 2026)

- **Humano-nas-exceções**: interrupt() do LangGraph, HITL do Google ADK 2.0,
  RequestPort do Microsoft Agent Framework, gates do CrewAI.
- **Control plane self-hosted**: Temporal, ADK api_server, OpenHands SDK
  server, LangGraph Platform (sob licença).
- **"AI builds the workflow for you" one-shot**: n8n AI Workflow Builder,
  Langflow Assistant, Sim Copilot, Gumloop, Lindy, Relevance Invent — todos
  sintetizam fluxo a partir de descrição, mas em design-time, uma vez, para
  o humano editar. Nenhum persiste grafo por classe de problema nem evolui
  topologia a partir de telemetria.

## Os dois vazios absolutos (em todas as frentes)

1. **engine-agnostico-cli + grafo**: ninguém orquestra Claude Code/Codex CLI
   por camada de abstração E gera/evolui o processo. A família de
   orquestradores de CLI (160+ projetos no índice awesome-agent-orchestrators)
   é quase toda "executar em paralelo com worktrees e review" — processo
   definido pelo humano, board que não aprende.
2. **propostas-gated de processo**: proposta registrada, versionada,
   aplicável com aprovação e rollback — sobre a TOPOLOGIA, não sobre prompt.
   O mais perto era o versionamento do OpenAI Agent Builder, que está sendo
   desligado (wind-down até nov/2026). Langfuse/Arize fecham esse loop só
   para prompt.

## Os seis mais próximos (verificados nas fontes oficiais)

- **AFlow** (FoundationAgents/MetaGPT, ICLR 2025 Oral, MIT) — o único que
  cobre o par-núcleo de verdade: MCTS sobre workflows representados como
  código, refinados entre rodadas por feedback. **Ressalva:** research-grade;
  a entrada é benchmark + métrica de score, não descrição de problema; sem
  control plane, sem humano, sem gates. github.com/FoundationAgents/AFlow
- **EvoAgentX** (MIT, ~3.2k stars, ativo) — o pacote mais completo:
  `WorkFlowGenerator.generate_workflow(goal)` gera WorkFlowGraph de objetivo
  em linguagem natural, HITL real, embute AFlow/TextGrad/MIPRO como motores.
  **Ressalva:** evolução benchmark-driven; versionamento é save/load sem
  trilha proposta→aprovação→rollback; sem servidor; sem CLIs.
  github.com/EvoAgentX/EvoAgentX
- **ADAS / Meta Agent Search** (Apache 2.0) — fundou a geração automática de
  topologia (meta-agente escreve forward() em código). **Ressalva:** exige
  benchmark com evaluate_forward_fn e dados rotulados; busca offline.
- **EvoFlow / ScoreFlow / MaAS** — população de workflows heterogêneos com
  seleção por query na inferência; números fortes vs AFlow. **Ressalva
  grave:** repo oficial do EvoFlow não existe; linha ainda é paper.
- **Langflow / n8n / Sim / Lindy / Gumloop / Relevance** — síntese one-shot
  em builder visual; sem contratos entre nós, sem evolução de topologia por
  telemetria.
- **Vizinhos notáveis da onda CLI**: Omnara (Apache 2.0; control plane +
  humano-como-entidade com perguntas bloqueantes e push — sem grafo, sem
  evolução); vibe-kanban (server Rust+SQLite, 10+ engines abstraídos —
  empresa morta, board não aprende); GraphCode (grafo persistente com
  nós=sessões CLI — topologia desenhada à mão); gh-aw (processo como
  artefato versionado em git — editado por humano).

## Sinais de mercado

- A camada de execução comoditizou: Terragon morto, vibe-kanban abandonado,
  Claude Code absorvendo background agents e cloud sessions nativamente.
  Conductor levantou US$ 22M ainda apostando em execução+review.
- A pesquisa 2025-26 valida a direção sem ocupá-la: AgentConductor (regenera
  topologia YAML por feedback de execução), InfiAgent, survey "From Static
  Templates to Dynamic Runtime Graphs" (arxiv.org/html/2603.22386v1). Todas
  exigem benchmark+métrica; nenhuma empacotou control plane + humano + gates.
- DSPy/GEPA é a única linha de "self-improvement" produtizada de verdade
  (Databricks), e otimiza TEXTO dentro de topologia fixa — não processo.

## Implicações de posicionamento (para o artigo e o produto)

1. O diferencial a defender não é "gerar grafo" (commodity no no-code) nem
   "orquestrar CLIs" (commodity na onda 2026): é o **casamento** — grafo com
   contratos, executado por CLIs abstraídos, **evoluindo por telemetria de
   produção** (não benchmark) **com propostas gated**.
2. "Telemetria de produção como métrica" é a resposta ao requisito de
   benchmark que trava toda a linha acadêmica: o log real substitui o
   dataset rotulado. É a ponte flowpilot→cartografo e o argumento central.
3. A morte da camada de execução é vento a favor: o valor está migrando
   exatamente para a camada que o cartografo ocupa. O risco simétrico:
   players grandes absorvem features rápido (Claude Code já absorveu a
   execução); o fosso é o loop de evolução com governança, não a execução.
