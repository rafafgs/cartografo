## Holes found (none of them became a ticket — creating a ticket is Rafael's decision)

1. **`testar-alpha` is incompatible with the claude-code adapter by construction** (a network
   with `domains`) — factory bundle 1 never gets past the integration with the only engine
   that really exists. Either the skill declares a network with no domains/closed, or the
   adapter learns domains.
2. **A pre-session failure that goes unrecognised becomes an infinite lease loop** — 38
   leases in 2 min, with no session, no ceiling and no block. `pre-session-failure.ts` knows
   only five patterns and t265 only counts failed sessions; a reproducible
   `SessionStartError` should block the job on the first occurrence, like an engine refusal.
3. **The executor does not advance `main` after the integration** (the skill promises that it
   does); testar and implantar read a main line that never received the work. The operator
   did the fast-forward by hand.
4. **`aplicacao`, `banco_de_testes`, `referencia`, `arquivos_de_registro`: input nobody
   produces** (the same family as bets' hole 5) — on the bench they came from `project`; in
   the real flow they have to come from the executor (the test bench = a checkout of the
   integrated main; the reference = the commit of the installation).
5. **These repeat here, and that is why they were pre-mitigated in the variant**: the skill's
   schema invisible to the model (bets' hole 1) and a routing node with a strict schema and no
   `resultado` (hole 4). With the mitigation, all three reports were accepted first time —
   evidence that the fix is exactly that (rendering the skill's schema into the prompt).
6. **`import` refuses `lineage: variant`** — a project variant only through the fork (D13).
   Correct in steady state; on a bench, the operator ends up lying `base`.
7. **Orphaned worktrees**: six `worktrees/ticket-1-*` for three sessions (one per dispatch
   attempt, including the ones that failed before opening a session); none is removed at the
   end.
8. **Does the runner do `npm ci --offline`?** No — every session did it itself because the
   worktree is born with no `node_modules` and the network is closed; it worked off the npm
   cache. It is worth a worktree-preparation step by the executor (flowpilot has one).

## What the round proves and what it does not

It proves: with a real repository and a request the size of a ticket, the software graph
refines an executable spec, implements it in an isolated worktree with tests first,
integrates and re-verifies the gates — three agent sessions, three accepted reports, code
that passes 289 tests and does what the request asks (all three alien varieties are born,
walk at their own speeds and die to a punch, a kick and a shot; contact with any of them
costs a life). With bets' holes 1/4 mitigated in the variant, the projection carried one
node's output to the next with no operator across `refinar → desenvolver → integrar` (the
`ticket.especificacao` and the `artefato.branch` arrived). And the flow topografo, for the
first time, proposed a change of topology.

It does not prove: `testar` and `implantar` by an agent (an incompatible adapter; done by
hand); that the executor drives the repository (advancing `main`, preparing the test bench);
a cost per feature below the reference pipeline (≈ US$ 17 for 3/5 of the path, dominated by
cache reading in refinar/desenvolver — 7.5 M tokens read); and D16's ruler (parity with
flowpilot), which is Rafael's judgement over this report.

## What was still missing

- Closing hole 1 (`testar-alpha`'s permission) and hole 2 (the lease loop) before any n>1
  software round — without them the graph never reaches `implantar` with claude-code.
- Deciding whose job "advancing `main`" and "preparing the test bench" are (executor vs.
  skill vs. operator) and implementing it; until then, `testar`/`implantar` are theatre.
- Applying (or not) the topografo's proposal 1 (the `escrever-testes` node) and a realistic
  token ceiling per node — Rafael's decisions.
- If the feature pleases: a fast-forward of `~/vibe-game` from the clone (one line, above)
  and a `git push` of the game's repository — both of them founder's acts.
