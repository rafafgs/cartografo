# Related work — what already exists in this space (2026-08-14)

A sweep across 4 fronts (orchestration frameworks, productized research, the 2026
wave of CLI orchestrators, no-code + observability), 37 unique projects evaluated
against the README's 6 capabilities, and the 6 closest ones verified
adversarially against official docs and repositories.

What it found: the pieces exist separately, in families that do not talk to each
other. The pair this project is built on — synthesizing a graph and evolving it
between rounds — was not delivered together as a runtime capability by anything
read here. Below is what each front does deliver, so a reader can check that
reading rather than take it.

## What has already become a commodity (it differentiates nobody in 2026)

- **Human-on-the-exceptions**: LangGraph's interrupt(), Google ADK 2.0's HITL,
  Microsoft Agent Framework's RequestPort, CrewAI's gates.
- **A self-hosted control plane**: Temporal, ADK api_server, the OpenHands SDK
  server, LangGraph Platform (under licence).
- **One-shot "AI builds the workflow for you"**: n8n AI Workflow Builder,
  Langflow Assistant, Sim Copilot, Gumloop, Lindy, Relevance Invent — all of them
  synthesize a flow from a description, but at design time, once, for the human
  to edit. None of them persists a graph per problem class and none evolves a
  topology from telemetry.

## The two absolute gaps (across every front)

1. **engine-agnostic-cli + graph**: nobody orchestrates Claude Code/Codex CLI
   through an abstraction layer AND generates/evolves the process. The family of
   CLI orchestrators (160+ projects in the awesome-agent-orchestrators index) is
   almost entirely "run in parallel with worktrees and review" — a process
   defined by the human, a board that does not learn.
2. **gated proposals about the process**: a proposal recorded, versioned,
   applicable with approval and rollback — about the TOPOLOGY, not about a
   prompt. The closest was OpenAI Agent Builder's versioning, which is being
   switched off (wind-down through Nov 2026). Langfuse/Arize close that loop for
   prompts only.

## The six closest ones (verified against the official sources)

- **AFlow** (FoundationAgents/MetaGPT, ICLR 2025 Oral, MIT) — the only one that
  really covers the core pair: MCTS over workflows represented as code, refined
  between rounds by feedback. **Caveat:** research-grade; the input is a
  benchmark + a score metric, not a description of a problem; no control plane,
  no human, no gates. `github.com/FoundationAgents/AFlow`
- **EvoAgentX** (MIT, ~3.2k stars, active) — the most complete package:
  `WorkFlowGenerator.generate_workflow(goal)` generates a WorkFlowGraph from a
  natural-language goal, real HITL, embeds AFlow/TextGrad/MIPRO as engines.
  **Caveat:** benchmark-driven evolution; versioning is save/load with no
  proposal→approval→rollback trail; no server; no CLIs.
  `github.com/EvoAgentX/EvoAgentX`
- **ADAS / Meta Agent Search** (Apache 2.0) — it founded the automatic generation
  of topology (a meta-agent writes forward() as code). **Caveat:** it demands a
  benchmark with evaluate_forward_fn and labelled data; the search is offline.
- **EvoFlow / ScoreFlow / MaAS** — a population of heterogeneous workflows with
  per-query selection at inference; strong numbers against AFlow. **A serious
  caveat:** EvoFlow's official repository does not exist; the line is still a
  paper.
- **Langflow / n8n / Sim / Lindy / Gumloop / Relevance** — one-shot synthesis in
  a visual builder; no contracts between nodes, no evolution of topology from
  telemetry.
- **Notable neighbours from the CLI wave**: Omnara (Apache 2.0; a control plane +
  the human-as-entity with blocking questions and push — no graph, no evolution);
  vibe-kanban (a Rust+SQLite server, 10+ engines abstracted — the company is
  dead, the board does not learn); GraphCode (a persistent graph with nodes = CLI
  sessions — the topology drawn by hand); gh-aw (the process as an artifact
  versioned in git — edited by a human).
