## `problem_class` is a rename, not a migration

The class value is renamed in the same commit as the directory, and this is the
reasoning, recorded because the opposite call was available.

The only live copy of the old value is `graph.id` / `graph.class` in
`.cartografo/cartografo.db`. That file is the control plane's embedded SQLite
(D1) and it is git-ignored — a local, disposable dev artifact regenerated by
re-running `cartografo import`, which this ticket ran anyway (below). Per D7 the
repository is private and pre-launch: there is no shipped installation whose
rows a real user depends on. So there is nothing to migrate, and writing a
migration would be writing one for a database nobody has.

The alternative — rename the directory and leave the class Portuguese — was
rejected because every existing consumer already assumes the two strings are
identical (`scripts/publish-atlas-bundle.test.mjs` builds `CLASS_ONE` from the
same literal as `BUNDLE_ONE`; `docs/formats/atlas-bundle.md` specifies the atlas
as one subdirectory per class), so splitting them would introduce a permanent
inconsistency to avoid a one-command reimport.

If a future ticket ever needs `problem_class` history preserved across a real
deployment, that is a different act with a real migration script in it. This
ticket does not anticipate it.

## What the ticket did not know it was taking

### 1. `tests/no-portuguese-path-segments.test.mjs` would have gone red on a note

Anticipated by the refinement, and it happened exactly as written: adding the
stems `assimetric` and `desenvolvimento` makes the whole-tree gate bite the bets
closing note — `2026-08-24-bets-assimetricas-closing-note.md`, as it was named
then, under `notas/` — whose filename spells the retired name and which no ticket
of this series renames. (t305 moved the folder and t121 renamed the file, by
founder instruction, to `notes/2026-08-24-t293-closing-note.md`.) `notas/` joins
`packages/core/migrations/` in `FROZEN_TREES`, with the reason written down and
mirroring the sibling gate's standing `notas` carve-out
(`tests/no-portuguese-document-tree.test.mjs`'s `ALLOWED_SEGMENTS`). A new case
pins that the exclusion is a prefix and nothing wider: the same filename under
`notes/` is still an offender.

### 2. `tests/factory-bundle-closing-note.test.mjs` — NOT anticipated

This is the one the refinement did not see, and it is the interesting one.

t280's closing note has a `## What resisted translation` table, and this gate
checks every row of it against the live bundle: the named identifier must really
still be in the named file. One row is

> `desenvolvimento-de-software` | `grafo.json`, `README.md` | The `problem_class`
> and the directory name. Folder-and-package scope, explicitly t282's and
> explicitly out of t280's.

— a row that named its own successor, and that this ticket makes false. Three
ways out, two of them closed:

- **Edit the note.** Closed twice over: the gate's own header says t280's note
  "is history and is not to be edited to match a bundle it never described", and
  `notas/**` is out of this ticket's scope.
- **Write a t306 note and repoint `CLOSING_NOTE` at it**, which is the gate's
  standing advice. Closed on inspection: that advice covers a RETRANSLATION.
  `AT2` demands, per node, an old id, an old version and an old hash that all
  differ from the new ones, and renaming a folder produces none of the three.
  There is no honest t306 row to write.
- **Record it in the gate**, which is what shipped. `RETIRED_ROWS` holds one
  entry — the identifier and the ticket that retired it — and it does not SKIP
  the row, it INVERTS it: a retired identifier must now survive in none of the
  files the note names. A second test pins that every entry still names a row
  the note really has. Both halves red rather than go quietly blind, which is
  the discipline `FROZEN_TREES` and `ALLOWED_SEGMENTS` already follow.

The general lesson, and the reason it is written up rather than buried in a
commit: **a gate that reads a historical document against the live tree is a
gate that a later, legitimate change can make red.** When that happens the fix
belongs in the gate, not in the document — and the gate needs a place to put it
before the day arrives.

## Gotchas

1. **A gate that reads a historical document against the live tree will
   eventually red on a legitimate change.** See finding 2 above. It is not a bug
   in the gate and not a bug in the document; it needs a third place to put the
   discrepancy, and the honest shape is to invert the claim rather than skip it.
2. **`tests/factory-bundle-closing-note.test.mjs` pins the bundle's per-file
   LINE COUNTS.** Reflowing a paragraph in
   `factory-graphs/software-development/README.md` after a rename shortens a line
   — harmless — but joining two lines that now fit on one is not: it changes the
   count and reds the gate. Two candidate joins were left alone here for exactly
   that reason.
3. **`grep` for the joined directory path misses the `path.join` call sites**,
   which t282 documented and which held again. Measured on the tree as it stood:
   51 tracked files outside `notas/` carried either name, and 34 of them spell it
   as a bare quoted segment rather than as a path. Grep for the segment, not the
   path. (The ticket's own estimate was ~46 files; the sweep at implementation
   time found 51.)
4. **The two new stems are safe against the English replacements by luck of
   spelling, not by design.** `assimetric` does not match `asymmetric`
   (`ss`/`s`, `i`/`y`) and `desenvolvimento` matches nothing English. A less
   fortunate pair of names would have needed a whole-component rule.
